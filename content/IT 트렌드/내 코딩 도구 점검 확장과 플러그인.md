## 1. 무슨 일이 있었나

![[IT 트렌드/첨부/코딩 도구 점검/concept-tool-layers.png]]
*개념도. 네 사건을 내가 고른 도구, 그 안에 따라 들어온 것, 밖으로 나간 것으로 나눠 직접 그렸다.*

**Cursor 마켓의 가짜 확장.** 10월 29일 오전 2시 27분부터 오후 1시 35분(미국 태평양 시각)까지 Cursor 확장 마켓에서 `Anthropic.claude-code` 2.1.312와 2.1.313 변조본이 배포됐다. Cursor 공지는 이 버전이 "Anthropic이 만들지 않은" 것이고, 호스트와 사용자 정보를 보내고 공격자 SSH 키를 넣고 역방향 터널을 열려 했다고 적었다. 관리자 권한이 없는 대부분의 기기에서는 터널 단계가 실패했을 것이라고 봤다. StepSecurity는 Cursor의 초기 수치로 최대 5,000명이 받았고, 키 모양의 환경 변수 이름은 모았지만 값은 읽지 않았다고 정리했다. Anthropic은 자사 공식 채널 버전은 문제가 없다며 다음 버전을 2.1.314로 건너뛰었다.

**Postman의 몰래 설치.** 10월 25일 올라온 GitHub 이슈에 따르면 Postman 데스크톱 12.33.4가 자동 업그레이드 중 Claude Code와 Codex에 Postman 플러그인을 켜고, Codex에 세션이 시작될 때마다 Postman 스킬을 쓰라고 지시하는 시작 훅을 넣었다. 설치 프로그램이 그 훅을 스스로 승인하는 기록을 남겼고, 원격 MCP 서버(mcp.postman.com) 연결도 설정됐다. 제보자는 데이터 유출을 주장하지 않았다. Postman은 11월 5일 "이 변경을 되돌린다"고 답하고 이슈를 닫았다.

**PolinRider.** OX Security는 11월 4일, 정상 npm 패키지 17개 버전에 숨은 로더를 찾았다고 발표했다. 설치 단계가 아니라 패키지를 import할 때 실행되고, 서버 주소를 이더리움 거래 안에 숨겨 두고 읽어 온다. 합계 주간 다운로드는 약 1,400이고 암호화폐 탈취 기능이 있었다. 설치 스크립트만 막아서는 피할 수 없는 방식이다.

**Claude Code의 이메일.** 11월 5일 GitHub 이슈와 HN 글(1,577점)이 Claude Code가 계정 이메일을 웹사이트에 보낸다고 알렸다. Claude Code 팀원은 HN에서 로그인한 사용자의 이메일을 모델 문맥에 넣어 두었는데, Claude가 직접 curl 명령을 쓸 때 연락처로 User-Agent에 넣는 일이 있었다고 설명했다. 이메일을 문맥에서 빼는 수정은 다음 릴리스에 들어가고, 2.1.317부터는 이메일이 든 웹 요청이나 curl 명령 전에 확인을 묻는다고 했다. Claude가 스스로 실행하는 스크립트까지 모두 잡지는 못한다는 말도 덧붙였다.

## 2. 30분 점검표

Windows 기준이다. macOS와 리눅스는 같은 위치의 같은 파일을 보면 된다.

| 점검 | 명령이나 위치 | 기준 |
|---|---|---|
| 편집기 확장 버전 | `code --list-extensions --show-versions`, `cursor --list-extensions --show-versions` | Claude Code 2.1.312, 2.1.313이 없을 것 |
| SSH 키 | `~/.ssh/authorized_keys` | `svc-telemetry` 주석 키가 없을 것 |
| 공지에 나온 흔적 | `~/.config/smt.cmd`, `~/.config/smtk`, 시작 프로그램 `sysmon.cmd`, 예약 작업 `SysMon` | 모두 없을 것 |
| 에이전트 플러그인 | `~/.claude/settings.json` 의 enabledPlugins, `~/.claude/plugins/installed_plugins.json` | 내가 설치한 것만 있을 것 |
| 에이전트 훅과 MCP | `~/.codex/config.toml`, `~/.codex` 아래 hooks, mcp 파일 | 모르는 시작 훅과 원격 MCP가 없을 것 |
| npm 의존성 | lockfile에서 OX 목록 패키지 이름 검색, `npm audit` | 이름이 없고, 높음 이상이 없을 것 |
| Claude Code 버전 | `claude --version` | 2.1.317 이상(이메일 확인 창) |

흔적이 나오면 확장을 지우는 것으로 끝나지 않는다. Cursor는 그 기기에서 쓰던 자격 증명과 세션을 다른 깨끗한 기기에서 바꾸고, 공식 정리 스크립트를 돌리라고 안내했다.

## 3. 써 본 기록: 내 노트북을 점검했다

2026년 11월 7일, 이 글을 쓰는 Windows 11 노트북에서 위 표대로 확인했다.

- **확장**: VS Code의 Claude Code 확장은 2.1.319, Cursor 쪽은 2.1.38이었다. 문제 버전 폴더는 없었다.
- **백도어 흔적**: `authorized_keys` 파일 자체가 없었다. 공지에 나온 파일, SysMon 예약 작업, ssh 터널 프로세스도 없었다.
- **Postman**: 11.85.1이 깔려 있었다. 문제가 된 12.33.4보다 낮고, Claude Code 설정에는 내가 직접 켠 플러그인 두 개뿐이었다. Codex 설정 파일은 없었다.
- **npm**: 이 PC의 lockfile(블로그 저장소 1개)에 OX 목록 패키지 이름은 없었다. 대신 `npm audit` 가 블로그 빌드 도구에서 높음 2건(sharp, source-map-js)과 보통 1건(minimatch)을 찾았다. `npm audit fix` 로 높음 2건을 고치고 블로그 빌드, 공유 이미지 생성까지 다시 돌려 확인한 뒤 반영했다. minimatch는 메이저 버전을 바꿔야 해서 남겨 뒀다.

점검하다 실수도 했다. 처음에 `npm audit fix --omit=dev` 로 돌렸더니 개발용 패키지가 지워져 빌드가 `Cannot find package 'esbuild'` 로 멈췄다. `npm install` 로 다시 받아 해결했다. 빌드 도구에 audit fix를 걸 때는 `--omit=dev` 를 빼는 편이 안전하다.

### Claude Code가 모델에게 보내는 요청을 직접 봤다

이메일 논란을 내 기기에서 확인하고 싶었다. 이 PC 안(127.0.0.1)에 요청 기록용 서버를 띄우고, Claude Code 2.1.319가 Anthropic 대신 그 서버로 요청하게 했다. 서버는 헤더 이름만 저장하고 값은 저장하지 않았다. 본문도 저장하지 않고 "계정 이메일이 들어 있나"만 기록했다. 모든 요청에 인증 오류를 돌려줘서 모델은 한 번도 돌지 않았고 비용도 들지 않았다.

![[IT 트렌드/첨부/코딩 도구 점검/result-email-capture.png]]
*직접 측정한 결과. 두 방식으로 실행했을 때 요청의 헤더, User-Agent, 본문에 계정 이메일이 있었는지 표시했다.*

API 키로 실행하면 요청 8번 모두 어디에도 이메일이 없었다. claude.ai 계정으로 로그인해 실행하면 요청 3번 모두 헤더와 User-Agent에는 없고, 모델에게 주는 문맥이 든 본문(약 11만 바이트)에 계정 이메일이 들어 있었다. Claude Code 팀원이 HN에서 설명한 그대로이고, 문맥에서 빼는 수정은 이 날짜까지 아직 들어가지 않았다.

본문에 이메일이 있다는 것 자체는 유출이 아니다. 그 요청은 원래 계정 주인인 Anthropic으로 간다. 문제는 모델이 그 이메일을 보고 다른 웹사이트로 가는 요청에 옮겨 적을 수 있다는 점이다. 그래서 2.1.317 이상의 확인 창이 중요하고, 확인 창이 뜨면 내용을 읽고 눌러야 한다.

## 4. 아쉬운 점과 확인할 점

- Codex CLI는 이 PC에서 실행 경로를 찾지 못해 같은 요청 실험을 하지 못했다.
- 확인 창이 실제로 뜨는지는 모델을 돌려야 볼 수 있어서 시험하지 않았다. 유료 API가 필요하다.
- Cursor 공지에는 받은 사용자 수가 없다. 5,000명은 StepSecurity가 전한 Cursor 초기 수치다. 일부 보도는 배포 경로를 Open VSX로 적었지만 StepSecurity와 Anthropic은 아니라고 했다.
- Postman 이슈에는 되돌린 버전 번호가 없고, 이미 설치된 사용자를 어떻게 하는지에 대한 답도 없다.
- OX와 Sonatype은 PolinRider 패키지 수를 다르게 셌다(17개 버전 대 10개 패키지의 12개 릴리스).

> [!note] 뉴리의 생각
> 1. 이번 네 사건은 모두 "내가 깐 도구가 또 무언가를 깐다"는 구조였다. 앞으로 개발 PC 점검은 설치 목록보다 에이전트 설정 폴더(`~/.claude`, `~/.codex`)의 훅과 MCP 목록을 먼저 보는 쪽이 맞아 보인다. 시작 훅은 매 세션마다 에이전트에게 지시를 넣을 수 있는 자리다.
> 2. 에이전트가 쓰는 요청을 사람이 매번 읽기는 어렵다. 이메일 같은 개인 정보를 아예 문맥에 넣지 않는 쪽으로 기본값이 바뀌어야 한다고 본다. 확인 창은 마지막 그물일 뿐이다.

## 용어 정리

| 용어 | 뜻 |
|---|---|
| 역방향 터널 | 안쪽 기기가 바깥 서버로 연결을 열어, 바깥에서 안쪽으로 들어올 길을 만드는 것 |
| 시작 훅 | 에이전트 세션이 시작될 때마다 자동으로 실행되는 명령이나 지시 |
| MCP | 에이전트가 외부 도구와 데이터에 연결하는 규격 |
| User-Agent | 요청을 보낸 프로그램을 알리는 HTTP 헤더 |
| lockfile | 프로젝트가 쓰는 패키지의 정확한 버전을 적어 둔 파일 |
| npm audit | 의존 패키지의 알려진 취약점을 찾아 주는 npm 명령 |
